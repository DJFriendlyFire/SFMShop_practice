# Стратегия хостинга для проекта SFMShop

## Оценка нагрузки

### Текущая нагрузка
- **RPS:** < 100 requests per second
- **Пользователи:** Небольшое количество
- **Трафик:** Низкий

### Ожидаемая нагрузка
- **RPS:** 100-500 requests per second
- **Пользователи:** Растущее количество
- **Трафик:** Средний

### Пиковая нагрузка
- **RPS:** До 1000 requests per second
- **Сценарии:** Рекламные кампании, распродажи

## Выбор хостинга

### Выбранный хостинг
**Cloud платформа (AWS, Google Cloud) с Kubernetes**

### Обоснование
- Автоматическое масштабирование для переменной нагрузки
- Высокая доступность для критичных операций
- Гибкость ресурсов для роста проекта
- Интеграция с другими сервисами (БД, кэш, очереди)

### Альтернатива
**PaaS (Railway, Render)** для быстрого старта и простоты развертывания

## Стратегия масштабирования

### Горизонтальное масштабирование
- Автоматическое масштабирование через Kubernetes HPA
- Минимум 2 реплики для отказоустойчивости
- Максимум 10 реплик для пиковой нагрузки

### Мониторинг
- Отслеживание RPS и latency
- Алерты при превышении порогов
- Автоматическое масштабирование на основе метрик

### Оптимизация
- Кэширование для снижения нагрузки на БД
- Оптимизация запросов к БД
- Использование CDN для статических ресурсов
